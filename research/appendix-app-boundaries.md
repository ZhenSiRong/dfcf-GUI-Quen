# 附录：东方财富「移动版 APP 模拟盘」的边界条件调研

> 调研目标：为「东方财富移动版 APP 模拟盘（模拟组合）」构建程序化交易系统之前，把**产品边界**钉死：
> ①APP 的「模拟」到底是不是一个 WebView？②模拟盘能交易什么、怎么撮合、收多少费？
> ③能不能参加炒股大赛、比赛是否禁止脚本？④条件单能不能用在模拟盘上？⑤程序化交易报备管不管模拟盘？

> 调研日期：2026-11-05。所有结论均带来源 URL；无法证实的明确标注 **未证实**。**没有任何 URL 是编造的**；凡引用原文均为逐字摘录。

## 优先级 1 —— APP 的「模拟」是不是 WebView？

### 1.1 结论拆解（三层，强度递减）

**（A）已证实：`groupwap.eastmoney.com` 承载完整的「模拟组合」H5 交易页。**
实测可访问（2026-11-05，HTTP 200）：

| 页面 | URL |
|---|---|
| 模拟组合买入 | `https://groupwap.eastmoney.com/group/simulation/buy.html?zh=<zjzh>&name=<名称>` |
| 模拟组合卖出 | `https://groupwap.eastmoney.com/group/simulation/sell.html?...` |
| 模拟组合撤单 | `https://groupwap.eastmoney.com/group/simulation/cancel.html?...` |
| 模拟组合持仓 | `https://groupwap.eastmoney.com/group/simulation/hold.html?...` |
| 模拟组合详情 | `https://groupwap.eastmoney.com/group/simulation/detail.html?zh=<zjzh>` |
| 创建模拟组合 | `https://groupwap.eastmoney.com/group/invest/create.html` |
| 模拟组合榜单 | `https://groupwap.eastmoney.com/group/invest/simulation.html` |
| 组合功能介绍 | `https://groupwap.eastmoney.com/group/invest/introduce.html` |

后端统一走 `POST https://emstockdiag.eastmoney.com/apistock/tran/getJson`，
表单字段 `path=zuheV64/JS.aspx` + `pageUrl` + `urlParm`（JSON 数组）。
`urlParm` 类型表（实测自官方前端 `buy_*.js` / `common_*.js`）：
`hold` / `user_infos` / `add_order` / `cancel_order` / `orders_valid` / `max_buy` / `max_sell`，
方向 `mmbz`（0=买, 1=卖），市场 `mkt`（1=沪, 0=深），`appVer` 9001000=查询、9002000=交易。

**（B）已证实（第一方证据）：`groupwap` 是"给东方财富 APP 内嵌用"的 H5 站点。**
官方前端 JS（`https://groupwap.eastmoney.com/group/static/script/reality/info/info_1776934691271.js`）里：

```js
t.emBase.Ready(function(){
  a.emDialog.emConfirm({
    content: "前往东方财富APP查看更多内容",
    execute: "前往",
    showPosition: 200,
    callback: function(n){
      if ("execute" == n){
        var r = i.helper.getUrlParameter("zh");
        window.location.href = "https://emstatic.eastmoney.com/awaken/app/share.html?linkType=828&zhid=" + r
      }
      ...
```

即：不在东财 APP 里打开这个页面，它会弹「前往东方财富APP查看更多内容」，点「前往」跳
`emstatic.eastmoney.com/awaken/app/share.html`（APP 拉起 / 分享落地页）。

第三方逆向项目 `LilianaMajamay/jiarenmens`（<https://github.com/LilianaMajamay/jiarenmens>）在
`src/config.py` 中把这条机制写得更清楚（**逐字**）：

```python
# groupwap.eastmoney.com 是东方财富 APP 内嵌 H5 站点。
# 站点 JS 通过 (UA 含 EMProjJs / EMRead 关键字) + (window.emh5 桥接对象存在) 判定 "在 APP 内"。
# 任一条件不满足就弹"前往东方财富APP"对话框，不渲染 detail-content。
_USER_AGENT = (
    "Mozilla/5.0 (iPhone; CPU iPhone OS 16_6 like Mac OS X) "
    "AppleWebKit/605.1.15 (KHTML, like Gecko) "
    "Mobile/15E148 EMProjJs-IPhone/EMRead 12.0.0 (em_appid/200)")
```

`window.emh5` 桥接对象的探测代码可在该仓库 `scripts/diagnose.py` 中看到：
```python
emh5: typeof window.emh5,
EMProjJs: typeof window.EMProjJs,
EMRead: typeof window.EMRead,
```

> ⇒ **「APP 内 WebView 会带上 `EMProjJs/EMRead` UA 标记并注入 `window.emh5` JS 桥」** —— 这就是
> "自动化手机 APP" 与 "自动化移动 H5" 能否等价的技术判据：**如果你能拿到带 `emh5` 桥的 WebView 会话，
> 你自动化的是 APP 内的那份 H5；如果 APP 的模拟 tab 其实是原生 RN 页面，那就完全不是一回事。**

**（C）未证实：APP 的「交易 → 模拟」tab 具体加载哪个 URL / 哪套后端。**
以下是我**实测做的 APK 静态分析**，它给出了**反证**（不是正证）：

* 我下载并解包了官方 APK：**`com.eastmoney.android.berlin` v11.5.5（2026-11-05 构建）**
  - 下载源（25PP 官方历史版本页，APK 直链可解析）：<https://www.25pp.com/xiazai/39395/history/>
  - 实测 URL：`http://android-apps.25pp.com/fs08/2026/11/05/7/110_db7f8b0cc4909f76810d9cc34c0048c9.apk?...&size=396361718&...`

  > 「**3、舞弊行为的处理办法是什么？** 主办方发现或选手被举报，经核实后确有**舞弊行为或违反交易规则等嫌疑**的，**立即取消选手参赛资格**，不再计算比赛成绩，由此产生的一切后果由选手承担。」

  A 股侧的对应条款（官方原文）：
  > 「公示期间，若发现名单中有**非在校生**，可向大赛承办方东方财富工作人员进行举报。工作人员在进行核实后，若情况属实，则**取消该用户的比赛成绩**。」

⇒ **判断：规则层面没有明文禁止自动化交易**，但"舞弊/违反交易规则"是开放式条款，
且赛事方掌握**成交明细 + 调仓时间序列 + 收益曲线**，自动化交易在"策略雷同度"上极易被判定异常。
⇒ **"用脚本参赛是否会被取消资格" = 未证实**（无官方说明），**但用官方 skill 参赛有先例（见 §3.7）**。

### 3.6 排名的反作弊敏感点（对程序化尤其致命）

因为排名只看收益率，且是**双周/周赛**：
* 港股大赛的「盈利提现奖」是「**以 50 万港元为计算基准 × 当期比赛收益率**」的万分之 1
  ⇒ **收益率越高，薅得越多**，且**收益率 > 2% 才可能提现**（低于 2% 不足 1 港币不发）。
  ⇒ **这是一个"短期高收益率刷奖"的强激励结构**，自动化刷收益率的动机天然存在。
* A 股侧要求「**至少产生一笔模拟下单交易**」，否则无成绩 ⇒ 纯刷不动手的账号无效。
* 榜单刷新：港股「交易日大赛排行榜每半小时刷新一次数据」。

### 5.2 「模拟盘是否在范围内」——**不在**

证监会《管理规定》**第二条**（从官方 PDF 逐字提取）：
> 「**第二条**　本规定所称**程序化交易**，是指通过计算机程序自动生成或者下达交易指令**在证券交易所进行证券交易**的行为。
> 　本规定所称程序化交易投资者，是指下列进行程序化交易的投资者：
> 　（一）私募基金管理人、合格境外投资者等证券公司的客户；
> 　（二）从事自营、做市交易或者资产管理等业务的证券公司；
> 　（三）使用证券交易所交易单元进行交易的公募基金管理人、保险机构等其他机构；
> 　（四）证券交易所认定的其他投资者。」

交易所《实施细则》**第三条**（上交所/深交所同文）：
> 「第三条　本细则所称程序化交易投资者，是指下列进行程序化交易的投资者：
> 　（一）**私募基金管理人、合格境外投资者、个人投资者等会员客户**；
> 　（二）从事自营、做市交易或者资产管理等业务的会员；
> 　（三）使用证券交易所交易单元进行交易的公募基金管理人、保险机构等机构；
> 　（四）本所认定的其他程序化交易投资者。」

* **"在证券交易所进行证券交易"** 是定义的核心限定 ⇒ **模拟盘的委托从未进入交易所**，**不在报告体系内**。
* 我在**深交所细则全文 PDF**（`szse_pgt.txt`，16 页）中 grep「模拟」「仿真」—— **0 命中**；
  全文**没有**任何"模拟交易/仿真交易予以豁免"的明文条款。
  ⇒ 结论是"**默示不在范围内**"，而不是"**被明文豁免**"。**这一点是「未证实」的**：没有哪份文件写"模拟盘豁免"。

⇒ **实操判定**：模拟盘做程序化 ⇒ **不需要向券商报备程序化交易**（因为压根没有会员账户、没有委托进交易所）。
但这**不等于**没有别的约束（用户协议 / 赛事规则，见 §5.6）。

### 5.3 个人投资者做实盘程序化：需要报告，但"能报"≠"能接"

**（a）报告义务 —— 含个人投资者。**
上交所细则第八条：
> 「**会员客户首次进行程序化交易前，应当向接受其交易委托的会员报告**，在会员对其提交的信息进行充分核查并确认无误后，方可进行程序化交易。会员收到客户报告后，应当及时向客户反馈确认并在**五个交易日内**向本所报告，本所接收后予以确认。」

> ⇒ **"先报告、后交易"** 是硬要求，且**个人投资者在范围内**。

**（b）高频认定标准（三所统一）**：
> 「将投资者交易行为存在**单个账户每秒申报、撤单的最高笔数达到 300 笔以上或者单日申报、撤单的最高笔数达到 20000 笔以上**情形的，认定为高频交易。」
（深交所细则 PDF 原文：「（二）单个账户单日申报、撤单的最高笔数达到 20000 笔以…」；
上交所细则发布说明同文；北交所答记者问同文 <https://www.bseinfo.net/important_news/200025377.html>）

**（c）异常交易行为四类**（沪深北实施细则统一）：
> 「**瞬时申报速率异常、频繁瞬时撤单、频繁拉抬打压、短时间大额成交**」四类程序化异常交易行为。
交易所负责人公开表态（上海市地方金融监管局转载上海证券报）：
> 「**从试运行情况看，触发相关指标的主要是量化私募、券商自营等机构投资者，中小个人投资者基本未发生相关情况**」

**（d）⚠️ 2026 年的关键收紧：个人投资者几乎没有合规的外接通道。**
《证券公司交易信息系统接入管理规范（试行）》**第六条**（官方全文逐字）：
> 「**第六条**　证券公司**可以向下列存在合理交易需求的客户提供交易信息系统接入服务**：
> 　（一）证券公司及其子公司、基金管理公司及其子公司、期货公司及其资产管理子公司、商业银行及其理财机构、保险公司及其资产管理公司、私募基金管理人；
> 　（二）合格境外投资者；
> 　（三）证券业协会认定的其他投资者。」

**第三十二条**：
> 「**第三十二条**　证券公司可以向下列客户提供**文件交互方式**的接入服务：
> 　（一）本规范第六条第（一）（二）项规定的客户；
> 　（二）其他经有关金融监管部门批准设立的信托公司等金融机构；
> 　（三）其他经基金业协会登记但不符合本规范第七条要求的私募基金管理人。
> 　**文件交互**是指证券公司交易客户端自动读取客户在电子文件等载体中记录的交易指令、解析并转成委托指令的接入方式。」

> ⇒ **普通个人投资者不在第六条名单里**，第三十二条的"文件交互"也同样不覆盖个人。

## 附录 C —— 给设计决策的三条硬结论

1. **模拟盘 = 组合系统，不是撮合柜台。** 它有 5 个交易动作（买/卖/撤单/委托/成交），
   **没有条件单**。所有"止盈止损/网格/时间触发"必须自己写。唯一有云端条件单的是**期货模拟账户**
   （但那是另一套品种、另一套账户、另一套规则），和**东财证券实盘 VIP 交易**（200 万门槛 / 仅 PC / 仅实盘）。

2. **公开组合 = 裸奔。** 实测未登录即可拿到完整持仓（代码/数量/成本/现价/仓位/盈亏），
   榜单还直接暴露"刚买了哪只、仓位多少"。**策略要保密 ⇒ 组合必须设为「对外隐藏」**（代价：不参与排名）。

3. **合规上最安全的形态是「官方 skill + 官方大赛」。** 东财自己办了「龙虾模拟炒股大赛」，
   明确让 AI 代理通过「妙想模拟组合管理 skill」操作模拟组合并按收益率发奖；
   而《证券公司交易信息系统接入管理规范（试行）》已经把普通个人投资者的实盘外接路堵死。
   ⇒ **把程序化限制在模拟盘 + 官方 API/skill 通道内，是当前监管与用户协议下唯一"既可做、又不踩线"的形态。**
