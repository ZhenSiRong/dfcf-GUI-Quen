## 1. 一句话结论

**不要去自动化「真·Android APP」。** 东方财富移动版模拟盘有一个**官方的移动 H5 网页版**（`groupwap.eastmoney.com`），和 APP 是**同一套模拟组合**（官方明文「web 端和 APP 端的投资组合数据是同步更新的」）。用 Playwright 驱动这个 H5 页面，**同样是「点 GUI 按钮」**，但稳定性比 uiautomator2 高一个数量级，开发量小 3-5 倍。

真正的效率瓶颈不在「怎么点」，而在**通道选择**和**登录态管理**。

## 2. 实测事实基线（本机亲手验证，非二手资料）

### 2.1 移动 H5 模拟盘 —— 可用，且是最佳 GUI 载体

```
GET https://groupwap.eastmoney.com/group/simulation/buy.html?zh=<zjzh>&name=<名称>
→ HTTP 200, title="模拟组合买入", 渲染无报错
```

DOM 要素（实测）：

| 要素 | 选择器 | 说明 |
|---|---|---|
| 买入价 | `#price` | placeholder `买入价格` |
| 买入数量 | `input[placeholder="买入数量"]` | 无 id |
| 按数量/按金额 | `input[name="selectType"]` value=0/1 | 单选 |
| 数量快捷 | `.minus` / `.add` / `1/4` `1/3` `1/2` `全仓` | |
| **模拟买入按钮** | `div.input.button`，文本 `模拟买入` | |
| 买入确认弹窗 | `.aui-dialog` → `.aui-dialog-btn`（取消/确定） | 确认前会复述代码/价格/数量 |
| 五档盘口 | DOM 内 | 刷新中，非交易时段全为 `--` |
| 持仓/成交/委托 | 三个 tab | |

后端（抓包实测）：

```
POST https://emstockdiag.eastmoney.com/apistock/tran/getJson
  path    = zuheV64/JS.aspx
  pageUrl = 当前页面 URL
  urlParm = JSON 数组
```

`urlParm` 类型表（源码 + 实测双证）：

| 用途 | urlParm |
|---|---|
| 持仓 | `[{"type":"hold"},{"recIdx":0},{"zh":<zjzh>},{"recCnt":100},{"appVer":"9001000"}]` |
| 资金 | `[{"type":"user_infos"},{"infoType":"zuhe_bal_info"},{"zh":<zjzh>},{"appVer":"9001000"}]` |
| **买入** | `[{"type":"add_order"},{"zh":<zjzh>},{"mmbz":0},{"mkt":1\|0},{"code":<6位>},{"price":<价>},{"vol":<量>},{"appVer":"9002000"},{"utToken":<ut>},{"ctToken":<ct>}]` |
| **卖出** | 同上，`mmbz:1` |
| 撤单 | `[{"type":"cancel_order"},...,{"orderId":<id>}]` |
| 可撤委托 | `[{"type":"orders_valid"},...]` |
| 最大可买/卖 | `[{"type":"max_buy"\|"max_sell"},...]` |

- 方向：`mmbz` **0=买，1=卖**
- 市场：`mkt` **1=沪，0=深**
- **无 token 下单实测返回**：`{"result":"-1","message":"ssoToken/ssoUToken/ssoCToken错误"}` → **下单必须带登录态**

### 2.2 PC 模拟盘交易台 —— 可用，但有坑

```
GET http://group.eastmoney.com/room/   → 200, jQuery 正常
```

- ⚠️ **HTTPS 下整页 JS 挂掉**：页面引用 `http://` 的 jQuery / topnav1200.js → Mixed-Content 拦截 → `$ is not defined`。必须用 `http://` 或 Playwright 路由重写
- 选择器：`#futcode` 代码、`#price` 价、`#codenumber` 量、`#btnOrder` 买入按钮
- **单击即下单，无二次确认弹窗**（比 H5 少一道，但也少一道防误单）
- 接口：`https://simoper.eastmoney.com/oper_tzzh_v2`（JSONP）
- ⚠️ 实测：**本机从页面上下文 / curl 直连 `simoper` 均超时或返回空 body**（DNS 117.184.33.94）。**走 H5 的 `emstockdiag` 则稳定 200** → 优先 H5

### 2.3 行情源 —— 直连可用，无需浏览器

```
GET https://push2.eastmoney.com/api/qt/stock/get?secid=1.600519&ut=b2884a393a59ad64002292a3e90d46a5&fields=f43,f57,f58,f60,f170
→ {"data":{"f43":145200,"f57":"600519","f58":"贵州茅台","f60":144644,"f170":38}}
```

curl 直连成功。**价格不读 UI，从行情 API 取**（UI 上的价格 3 秒刷新、且非交易时段是 `--`）。

### 2.4 官方妙想 API —— 存在，但是「限额」换「免 GUI」

`POST https://mkapi2.dfcfs.com/finskillshub/api/claw/mockTrading/{positions,trade,cancel,orders,balance}`，Header `apikey`。

- 免费版 **50 次/天** + 限时加赠 **100 次/天** ≈ **150 次/天**
- 休眠账户降到 **10 次/天**；进阶 300 / 旗舰 600
- 判定：`code=="200"` **且** `data.rc==0`；委托号字段 `data.orderID`
- 响应金额单位是**厘**（÷1000 = 元）
- **它操作的就是你自己那个模拟组合**（Skills 页面「请选择已有建沪深模拟组合进行绑定」）
- 需在东财 APP 内领 Key（每日限量 5000 名）

### 2.5 本机环境

| 项 | 状态 |
|---|---|
| OS | Ubuntu 24.04, 12 vCPU, 15 GB RAM（**当前可用仅 2.6 GB**，被一台 Windows VM 占 5.3 GB） |

| 浏览器 | Google Chrome 155（`/opt/google/chrome/chrome`） |

| 自动化 | `playwright-core`（Node）可用，复用系统 Chrome，无需下载内核 |

## 3. 「只能 GUI」这个约束的真实解法

东财体系里能下单的通道，从「最像 GUI」到「最不像 GUI」：

| # | 通道 | 是不是 GUI | 本机可用 | 限额 | 开发量 | 稳定性 |
|---|---|---|---|---|---|---|
| A | **移动 H5 + Playwright**（`groupwap`） | ✅ 真 GUI（移动网页） | ✅ 实测通 | 无 | 2-3 天 | ★★★★☆ |
| B | PC 交易台 + Playwright | ✅ 真 GUI | ⚠️ simoper 超时 | 无 | 2-3 天 | ★★★☆☆ |
| C | 官方妙想 API | ❌ 官方 API | ✅ | **150 次/天** | 半天 | ★★★★★ |
| D | 真·Android APP + uiautomator2 | ✅ 真 GUI | 需装模拟器 | 无 | 2-3 周 | ★★☆☆☆ |
| E | 直连 `emstockdiag` / `spo_order` | ❌ | ✅ | 无 | 1 天 | ★★★★☆ |

**推荐 A 为主，C 做独立对账源。** 理由：

1. **A 就是「移动版模拟盘」本身**。官方明示 APP 与 web 端组合数据同步 → 用 H5 下单，APP 里立刻看得到持仓/成交。满足「移动版」这个语义要求。
2. **D 的一切痛点 A 都没有**：不用处理 App 版本漂移、模拟器分辨率、指纹/资金密码弹窗、OCR 读价、行情刷新导致的控件抖动。H5 的 DOM 稳定、可用 `page.waitForResponse` 精确等下单响应。
3. **C 的 150 次/天** 只够低频调仓，撑不起盘中；但**正好够做每日对账**（独立第三方核对持仓/成交）。
4. **E 留作应急通道**：H5 万一下线或改版，直接降级到直连，不重构上层。

## 4. 推荐架构

```
┌──────────────────────────────────────────────────────────┐
│ 策略层  Strategy        纯函数，无 IO。输出 TargetPosition[] │
│   - 输入：行情快照 + 组合状态                            │
│   - 输出：目标仓位 / 目标委托                            │
├──────────────────────────────────────────────────────────┤
│ 风控层  RiskGuard       单票上限、总仓位、单日笔数、        │
│                         单笔金额、连败熔断、价格偏离拒单     │
├──────────────────────────────────────────────────────────┤
│ 调度层  Scheduler       cron/事件驱动；避开清算与竞价      │
├──────────────────────────────────────────────────────────┤
│ Broker 适配层（可插拔）                                   │
│   interface Broker:                                      │
│     positions() / balance() / orders()                   │
│     place(buy|sell, code, price, qty) -> OrderResult     │
│     cancel(orderId)                                      │
│   ├─ WapBroker    Playwright → groupwap  H5   ← 默认      │
│   ├─ MxBroker     妙想官方 API                ← 对账/兜底  │
│   └─ AppBroker    uiautomator2 → 真 APP        ← 最后兜底  │
├──────────────────────────────────────────────────────────┤
│ 数据层  MarketData       push2 / push2his 直连 API         │
│                        行情、K线、盘口，指数退避             │
├──────────────────────────────────────────────────────────┤
│ 持久层  Store (SQLite)  信号、委托、成交、持仓快照、       │
│                        资金流水、错误日志、截图            │
└──────────────────────────────────────────────────────────┘
```

**策略层永远不感知通道。** 这是本方案的核心：通道会坏（妙想限额、H5 下线、APP 改版），策略不该跟着改。

## 5. 关键工程决策（都是实测出来的，不是猜的）

| # | 决策 | 依据 |
|---|---|---|
| D1 | **价格走 push2 API，不读 UI** | UI 价格 3 秒刷新、非交易时段显示 `--`；UI 读价会引入陈旧价 |
| D2 | **登录态复用**：人工登录一次 → 存 `storage_state.json`（cookie `ct`/`ut`/`uid`）→ 复用；下单时带 `utToken`/`ctToken` | 实测无 token 下单报 `ssoToken/ssoUToken/ssoCToken错误` |
| D3 | **过期自动重登**；若弹短信/图形验证码 → 推送到手机，人工点一次，续用 | 验证码无法稳定自动化 |
| D4 | **下单前「快照核对」**：读回输入框实际值 vs 独立算出的期望值，一致才点确认 | 模拟盘撮合规则「买价≥最新价按最新价成交」→ **填错数量/方向 = 立刻真金成交**，价格填错反而只是不成交。数量和方向才是致命项 |
| D5 | **限价单而非市价单** | 官方 FAQ 未提市价单；限价可控 |
| D6 | **调度避开** 9:15-9:30（集合竞价价格无意义）、11:30-13:00（午休）、**15:00-17:00（清算期不可接受委托）**；14:55 前完成下单 | 官方 Q037 |
| D7 | **下单后 5s 轮询成交状态**（官方页面本身就是 5s 刷新） | 与官方节奏一致，不打爆接口 |
| D8 | **模拟盘规则写进回测引擎**：T+1、买入 100 股整手、佣金千一双向（含过户费）+ 印花税千一卖出、涨跌幅限制、当日未成交自动撤销 | 否则「回测赚钱、模拟盘不赚钱」 |
| D9 | **熔断**：日下单次数上限、连续 N 次失败即停并告警、下单前独立行情校验价格偏离 < 3% | |
| D10 | **完整日志 + 截图**：每次下单前存截图 + 填单值 + 预期值，便于事后复盘 | GUI 自动化的核心是可审计 |
| D11 | **模拟盘 ≠ 实盘**：撮合过于理想（零滑点、买价≥最新价按最新价成交）、佣金千一 vs 实盘万2.5 → 收益数字本身没有投资意义，**只用来验证工程管道和策略逻辑** | 官方 Q037 |

## 6. 里程碑

| 里程碑 | 内容 | 产出 | 估时 |
|---|---|---|---|
| **M0** 账号与登录打通 | 人工登录一次 → 存 `storage_state` → Playwright 打开 H5 买入页，能看到**自己的**组合与持仓（**不下单**） | `auth/` 模块 + 一份可复用登录态 | 0.5 天 |
| **M1** 只读探针 | 读持仓/资金/委托/成交 → 落 SQLite；同时接 push2 行情做价格源 | `broker/wap.py` 只读部分 + schema | 1 天 |
| **M2** 下单闭环 | dry-run → 真实下 1 手（600519）→ 查成交 → 撤单；带 D4 快照核对 + 熔断 | `broker/wap.py` 写部分 + 单测 | 1 天 |
| **M3** 策略骨架 | 一个最小策略（均线或网格）+ Scheduler（避开清算）+ 日志 + 复盘报表 | `strategy/` `scheduler/` | 1-2 天 |
| **M4** 冗余与对账 | 接入妙想 API 做每日独立对账；H5 失效时降级路径 | `broker/mx.py` + `reconcile` | 1 天 |
| *(可选)* M5 | 真 APP 通道（uiautomator2），仅当 WAP/H5 不满足需求时 | `broker/app.py` | 2-3 周 |

**M0 是全部的门槛**：登录态拿不到，后面全白做。

## 7. 已识别的风险与未知

| # | 风险 | 缓解 |
|---|---|---|
| R1 | H5 页面可能随时下线（`groupwap` 属官方未公告资产，实盘组合部分已迁 `spzhapi`） | M4 兜底 + 通道可插拔 |
| R2 | 图形验证码 / 短信验证码打断登录 | D3 人工介入一次 |
| R3 | `ct`/`ut` 会话有效期未知（未证实） | 每次下单前用只读查询验活；失效则重登 |
| R4 | 弹窗风暴（营销/活动/风控） | Playwright `watcher` + 选择器白名单 |
| R5 | 成交价 3 秒刷新 → 委托可能不按预期成交 | 限价 + 成交后核对 |
| R6 | 东财用户协议禁「插件/外挂/第三方软件干扰」，且明确适用移动客户端 | 模拟盘不涉真实资金；限频（人节奏）；完整日志；不绕验证码批量注册 |
| R7 | 《证券市场程序化交易管理规定》**不区分是否 GUI**；个人/模拟盘是否需报备**未证实** | 需用户自行判断 |
| R8 | 本机内存仅剩 2.6 GB | M5 若做 Android 模拟器需先释放 |
| R9 | 行情接口 push2 高频会被封 IP（社区实测 5 分钟 500 条） | 指数退避 + 批量拉取 |

## 8. 待用户决策（grill 议题）

1. 「只能 GUI」的准确含义 —— 是必须点真 APP 的按钮，还是「走官方页面/官方通道即可」？
2. 系统范围 —— 只要下单执行器，还是完整量化系统（含策略/回测/风控/监控）？
3. 交易频率 —— 日内还是日终？直接决定妙想配额够不够。
4. 是否允许最后一步人工确认？
5. 部署形态 —— 7×24 常驻在哪台机器？
6. 现有账号资产 —— 有没有东财通行证？有没有已创建的模拟组合（`zjzh`）？
